1. Introduction¶

1.1 Policy-aware SISA configuration sensitivity experiment¶

This notebook evaluates a deliberately policy-aware SISA assignment added after the standard SHA-256 recipient assignment produced no shard reuse. It is a configuration sensitivity experiment, not a silent replacement for standard hashed SISA.

Exact membership in the five predefined deletion policies is used before training to localise known requests. That is an optimistic system-design assumption and may not generalise to unknown future deletions. The original hashed notebook, assignments, models and results remain immutable comparison evidence.

1.2 Research aim and questions¶

The aim is to test whether an assignment designed around the five known deletion policies changes SISA locality, runtime, retained utility and similarity to full retraining.

  1. Does the policy-aware assignment reduce affected shards and replayed stages?
  2. Are unaffected original policy-aware shard models reused byte-for-byte?
  3. How does retained utility compare with baseline, full retraining and hashed SISA?
  4. How close are policy-aware truth ratios to matching full-retraining truth ratios?
  5. Do measured sequential runtimes improve, and what structural change explains them?

1.3 Scope boundaries¶

Dataset, identity data, permanent splits, deletion memberships, 18 features, preprocessing, architecture, threshold and training settings are unchanged. Assignment uses only training recipient/donor IDs, exact training-forget policy masks and seed 42. Targets, clinical features, predictions, test results, utility, KS and runtime never construct or select the assignment.

The target is inspected only after assignment as an audit. Results are descriptive, do not establish privacy or erasure, and do not imply policy-aware SISA is the standard or universally superior configuration.

4.3 Optimise the policy footprint lexicographically¶

A small aggregated integer programme uses only component size and policy bitmask. Phase 1 minimises the maximum affected shards; Phase 2 fixes that optimum and minimises total affected scenario-shards. Shard labels are then canonicalised by structural role, eliminating solver-label symmetry. No model quantity is available at this stage.

def build_footprint_problem(components):
    type_counts = Counter((item["policy_mask"], item["recipient_count"]) for item in components)

4.4 Assign components to balanced shards and late slices¶

Components with fewer feasible policy shards are placed first. Stable hashes break ties after choosing the least-loaded feasible shard. Within each shard, rarer known-policy components are placed into the latest balanced slices; a deterministic same-size local-swap pass checks for any replay-stage improvement. Balance is fixed before target audit.

def assign_component_shards(components, footprint):

def restore_for_replay(shard_id, earliest_slice):
    """Restore the state immediately before the replay suffix, or initialise fresh."""
    initialization_seed = derived_seed("policy_aware_original", shard_id)
    reset_seed(initialization_seed)
    model = BaselineMLP()
    optimizer = torch.optim.AdamW(model.parameters(), lr=LEARNING_RATE, weight_decay=WEIGHT_DECAY)
    # Replay starts immediately before the earliest affected slice to preserve valid prior work.
    if earliest_slice > 1:
        path = ORIGINAL_DIR / f"shard_{shard_id}_slice_{earliest_slice - 1}.pt"
        checkpoint = torch.load(path, weights_only=False)
        model.load_state_dict(checkpoint["model_state_dict"])
        optimizer.load_state_dict(checkpoint["optimizer_state_dict"])
    return model, optimizer, initialization_seed

9.2 Limitations¶

This is an optimistic policy-aware SISA configuration sensitivity experiment added after standard hashed SISA showed no shard reuse. Exact membership in the five known policies shaped shard and slice placement. Unknown, novel or distributed future requests may again reach all shards and early slices. The target and model results were excluded from assignment, but policy locality itself is privileged foreknowledge.

SISA remains a five-model ensemble while full retraining is a single model; KS distance is a common project comparison but cannot isolate deletion fidelity from architecture. A lower KS statistic or higher p-value is not proof of erasure. Runtime is hardware-dependent and includes checkpoint/ensemble overhead. The frozen preprocessor is not unlearned. One split, seed and configuration cannot establish universal performance, privacy or clinical validity.

9.3 Role in the wider project¶

The standard hashed result remains the default SISA evidence. This post-hoc policy-aware experiment tests configuration sensitivity only and should be presented separately in the dissertation discussion.
